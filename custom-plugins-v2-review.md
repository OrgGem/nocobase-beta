## 1. Kết luận chung

- **Kiểm tra tự động (toàn bộ `src/client-v2` của 59 plugin)**

Không được diễn giải thành “0 lỗi type của plugin”; `skipLibCheck` không bỏ qua lỗi parse này.
  - Vitest (client env), đã chạy lại: **72 file / 270 test pass**. Trong đó 71 file / 241 test nằm dưới `__tests__`; `plugin-api-manager/src/client-v2/utils/usage.test.ts` nằm ngoài thư mục đó, chạy riêng có 29 test pass. Kết quả gồm unit, registration/smoke và component tests; chưa phải browser E2E hay xác nhận feature parity đầy đủ.
  - ESLint: báo cáo ban đầu ghi 1 cảnh báo `react-hooks/exhaustive-deps` và 7 lỗi prettier ngoài lỗi line ending; lượt hiệu chỉnh chưa chạy lại toàn bộ ESLint nên giữ các số này như bằng chứng cũ, chưa tái xác nhận. Khoảng 68.000 thông báo `Delete ␍` phản ánh checkout Windows; không tính thành 68.000 lỗi logic hay yêu cầu format toàn repository. Khi sửa code, chạy `yarn eslint --fix` trên các file được chạm và kiểm tra diff.
  - Scan import trực tiếp chưa thấy `@nocobase/client` trong các file client-v2. Một số file dùng tiện ích Formily (`useForm`, `connect`, `mapReadPretty`) như core v2. ### 2.2. v2 import từ thư mục lane v1 (`../client/**`) — 13 plugin

Các dependency tree đã đọc không cho thấy các entry này kéo `@nocobase/client` vào v2; nhiều file đã dùng client-v2 hoặc là helper thuần. Vẫn nên làm rõ quyền sở hữu và hướng dùng chung theo AGENTS.md, nhưng chưa đủ cơ sở xếp HIGH chỉ vì đường dẫn `../client/**`. Ưu tiên đặt React UI dùng client-v2 trong `src/client-v2/` và để v1 import lại; dùng `src/shared/` cho logic độc lập runtime. Trước khi chuyển cả cây UI sang shared, kiểm tra server build glob (`src/**` loại trừ hai thư mục client) để tránh vô tình đưa UI vào server output.

- MEDIUM (tổ chức mã dùng chung): plugin-antd-style-theme, plugin-ai-browser, plugin-build-guide-block, plugin-build-ui-template, plugin-cluster-manager, plugin-data-cloner, plugin-embed-web-client, plugin-git-manager, plugin-knowledge-base, plugin-package-registry, plugin-user-memory.

- MEDIUM: plugin-visualization-templates dùng chung registry/helpers qua `src/client`; cần tách helper khỏi module schema v1. Chưa đo bundle nên chưa khẳng định phần schema không được dùng còn lại sau tree-shaking.

### 2.4. i18n namespace và cơ chế fallback

Locale bundle của plugin được server đăng ký theo đúng tên package (`packages/core/server/src/locale/locale.ts:168-178`; dạng ngắn chỉ có với prefix `@nocobase/plugin-`). Các namespace sau không khớp:

- Namespace lệch package: `'@nocobase/plugin-n8n'`, `'@nocobase/plugin-uipath-orchestrator'`, `'cluster-manager'`, `'ai-drawio'`. `ai-browser` và `antd-style-theme` cũng dùng tên ngắn, nhưng loader v2 hiện copy bundle sang namespace đó; không kết luận bản dịch v2 của hai trang này không bao giờ áp dụng. Chuẩn hóa namespace rồi kiểm tra đổi ngôn ngữ trước/sau khi mở tab để loại bỏ phụ thuộc thứ tự load.
- `useTranslation()` không có namespace (defaultNS của client-v2 là `client`, không fallback): plugin-router-configuration, plugin-build-guide-block, plugin-data-source-elasticsearch, plugin-data-source-mssql.
- `ctx.t()` trong `uiSchema` không truyền `ns`: plugin-block-embed-settings.
- Mẫu đúng: `locale.ts` kiểu plugin-block-iframe (`tExpr`/`useT` với `ns: [pkg.name, 'client']`).

- `@nocobase/test` nằm trong `peerDependencies` ở rất nhiều plugin (không phải runtime peer; bỏ).

## 5. Phụ lục: ghi chú xuyên suốt của từng nhóm review

#### Nhóm A1

1. **Lane sharing is inconsistent.** Three plugins keep a second copy of v2-only code for the v1 lane (`plugin-block-cross-join`, `plugin-block-timeline`) or import across lanes (`plugin-build-guide-block` v2 -> `../client/`). Since every one of those files only depends on `@nocobase/client-v2`/`@nocobase/flow-engine`, the fix is the same everywhere: one copy under `src/shared/` (or `src/models/`), imported by both `src/client` and `src/client-v2`. `plugin-block-json` and `plugin-advance-charts` already do this correctly (v1 re-exports v2).
2. **`ctx.t` without namespace inside `uiSchema(ctx)`** silently loses plugin translations (`plugin-block-embed-settings`); plugin keys are only registered under the package-name namespace. Use the plugin `tExpr`/`tStr` helper for every label in flow steps.
3. **Flow declaration pitfalls**: Cross Join has neither a settings schema nor an explicit/manual trigger, so core includes it in beforeRender and omits its settings step. Other uiMode types such as select/switch can appear without a schema; do not generalize the Cross Join condition to every step. Fix with an actual settings form and a side-effect-free handler, or an explicitly invoked custom setting; test mount/close/reopen and persistence.
4. **i18n helper drift**: four plugins use `react-i18next` `useTranslation` or flow-engine `tExpr` with a literal ns instead of a per-plugin `locale.ts` (`useT`/`tExpr` bound to `pkg.name`). Not broken, but a small shared template would prevent the namespace mistakes above.
5. **Manifest nits repeat**: `files` shipping `src`; `@nocobase/test` listed as a runtime peer (5 of 7); `@nocobase/flow-engine` imported but not declared (advance-charts, block-json); `devDependencies` present in cross-join (unneeded) and build-guide (justified typings); `plugin-block-json` uses non-array `supportedVersions` and string `editionLevel`.
6. **Theming**: hard-coded light colours in block UIs (`cross-join`, `json`, `timeline`, `build-guide`) — use antd v5 tokens / `--ant-*` CSS vars for dark mode.
7. **Global side effect to verify**: `plugin-block-json` rebinding the default display model for the `json` interface app-wide.
8. Tests: present and behavioural in advance-charts, embed-settings, block-json, timeline, build-visualization; missing in cross-join and build-guide.

#### Nhóm A2

- **Lane duplication is the dominant pattern.** Four of six plugins keep a second copy of v2 code under `src/client/` (full copy: plugin-field-selection-filter, plugin-visualization-templates manager, plugin-ocr-verify-block model; thin re-export: plugin-field-fast-render, plugin-field-style-format, plugin-header-style-format). Only plugin-ocr-verify-block uses a lane-neutral `src/shared/` folder. Recommend one of two conventions per plugin: (a) `src/client/*` re-exports `../client-v2/*` (v1 -> v2 import is allowed) when there is no v1-specific UI, or (b) `src/shared/` for pure logic when both lanes have real UIs. plugin-visualization-templates is the only plugin where v2 imports *from* `src/client/` (reverse direction); runtime-safe today but should be fixed before `schema.ts` grows a `@nocobase/client` import.
- **Core-model extension pattern.** The three table-column plugins extend the core `TableColumnModel` three different ways: flow registered in `load()` with a Symbol once-guard + prototype patch (fast-render), flow registered at module import (style-format, header-style-format), flows registered in `load()` on four core models with `defineAction` (selection-filter). All verified to hit real core hooks (`props.onCell` at `TableColumnModel.tsx:286`, `...this.props` spread at `:273` for `onHeaderCell`, `renderItem()` via `CollectionFieldModel.render()`). Pick one convention (prefer `load()` + once-guard) so plugins can be enabled/disabled without import side effects.
- **Manifest drift (all six).** Missing `displayName.zh-CN` in all six; `keywords` as a string in fast-render and visualization-templates; `@nocobase/test` listed in `peerDependencies` in four plugins (fast-render, selection-filter, style-format, header-style-format); fast-render's `client.js` points at the v2 bundle; visualization-templates has `devDependencies`; ocr-verify-block has `displayName.vi-VN` only.
- **i18n is in good shape.** Every v2 string spot-checked goes through `tExpr`/`useT`/`this.t` and every key exists in both `en-US.json` and `zh-CN.json`; two plugins use `react-i18next` `useTranslation` for `useT` (matches several upstream v2 plugins).
- **Types/quality.** client-v2 lanes have zero `any`, zero `void x()`/async-IIFE, and the only `console.*` is the export-error log in visualization-templates. The only material `any` usage is in plugin-ocr-verify-block's server/shared code. The `// @ts-ignore` on `import pkg from '../../package.json'` appears in four `locale.ts` files and matches upstream (`plugin-field-code/src/client-v2/locale.ts:11`).
- **Tests.** All six plugins ship `src/client-v2/__tests__` with behavioural tests (not import-only smoke tests); selection-filter's v2 test is the thinnest (one flow of four).

#### Nhóm B1

1. **Where shared page components live** is inconsistent across the group. plugin-api-manager, plugin-app-observability and plugin-crypto-toolkit do it right: components in `src/client-v2/`, v1 lazy-imports them (allowed v1→v2). plugin-build-ui-template and plugin-cluster-manager do the reverse (v2 → `../client/**`, MEDIUM structural findings) even though those components are v2-pure; plugin-carbone-template-manager duplicates every component and papers over it with `adapters.ts`. One convention (`src/client-v2/` or `src/shared/`, v1 imports from there) fixes all three.
2. **Dependency verification**: Carbone and Cluster Manager require artifact/clean-install checks, not a blanket move from devDependencies to dependencies. NocoBase packages server dependencies; axios is external and file-saver is bundled for the browser. Carbone dry-run confirmed adm-zip/form-data are included. An undeclared build dependency remains a reproducibility concern, distinct from missing files in an installed artifact.
3. **`@nocobase/test` in `peerDependencies`** (api-manager, build-ui-template, crypto-toolkit) — test-only package, should not be a runtime peer.
4. **i18n**: two plugins with large gaps (api-manager 124 zh-CN gaps after core fallback (127 absent from plugin-local JSON); build-ui-template has no locale files at all) and one namespace bug that silently disables all translations (cluster-manager `ns: 'cluster-manager'` vs package name).
5. **Plugin-card Settings link**: menu keys differ from the package name in 5 of 7 plugins (`advance-settings`, `api-manager`, `ai-build-ui-template`, `carbone-template-manager`, `crypto-toolkit`). `PluginCard` (`core/client-v2/src/settings-center/plugin-manager/PluginCard.tsx:183`) shows its Settings button only when `pluginSettingsManager.hasPluginSettings(pluginName)`; v2 provides `setPluginSettingsLink(pluginName, menuKey)` for exactly this — call it in `load()`. Same behaviour as v1, so not a regression, but a one-liner improvement.
6. **ACL snippets** match the server in all 7 plugins; the only contract risk is carbone's nested-snippet `.settings` definition (MEDIUM, verify). Calls to other plugins' endpoints (`cryptoKeys:list`, `roles:list`, `storages:list`, `collections:list`, `ai:listLLMServices`) are outside each plugin's snippet; api-manager and crypto-toolkit handle the 403 gracefully, build-ui-template does not (verify).
7. **Tests**: only app-observability (page render tests), api-manager (`utils/usage.test.ts`) and cluster-manager (utils) have v2 client tests; advance-settings, build-ui-template, carbone, crypto-toolkit have none.
8. **v2 API usage is otherwise correct** everywhere: `Plugin` from `@nocobase/client-v2`, `addMenuItem` + `addPageTabItem` with `componentLoader` and default exports (verified for every loader target), `app.apiClient` / `useApp().apiClient` for requests, antd v5 throughout, no Formily / `SchemaComponent` / `@nocobase/client` imports in any `src/client-v2`, no `void x()` or async IIFEs, no `console.log`. Carbone's workflow node follows the upstream `Instruction` + `FieldsetLoader` contract.

#### Nhóm B2

1. **v2 → v1-folder dynamic imports (3 of 7 plugins)**: `plugin-data-cloner`, `plugin-embed-web-client`, `plugin-git-manager` register v2 menus/tabs correctly but satisfy `componentLoader` with `import('../client/...')`. In all three cases the imported components are already v2-pure (`@nocobase/client-v2` only), so the fix is a folder move to `src/common/` (or `src/shared/`), not a rewrite. `plugin-external-storage-manager` chose the opposite — copying files into `src/client-v2` — and now carries a byte-identical 774-line duplicate.
2. **ACL snippet naming for unscoped packages**: server-side `pm.${this.name}` resolves to `pm.plugin-<name>` for every plugin in this group (name is not trimmed for `plugin-` without `PLUGIN_PACKAGE_PREFIX`). Five plugins hardcode the long form on the client and are consistent; `plugin-docker-registry-ui` hardcodes the short form (`pm.docker-registry-ui.*`) and is therefore inconsistent (HIGH above); `plugin-embed-web-client` derives it from `this.options.name` (OK). `plugin-data-cloner` registers no snippet at all.
3. **Plugin-manager "Settings" link**: none of the seven calls `pluginSettingsManager.setPluginSettingsLink(<plugin name>, <menu key>)` although every menu key differs from the plugin name (`data-cloner`, `database-plus-manager`, `docker-registry`, `embed-web-client`, `external-storage-manager`, `git-manager`, `hashicorp-vault`). `hasPluginSettings('plugin-xxx')` (`packages/core/client-v2/src/PluginSettingsManager.ts:330-346`) therefore returns false and the plugin card in Plugin Manager shows no Settings entry. Upstream `plugin-environment-variables` does call it. LOW each, worth fixing in one sweep.
4. **Response unwrapping**: four plugins hand-roll the `{ data: { data } }` unwrap; `plugin-database-plus-manager` has one page that forgot it (HIGH). A shared `unwrap<T>(response)` per plugin (docker-registry-ui `api.ts:27` is a good template) avoids the class of bug.
5. **`@nocobase/test` as a peerDependency** appears in `plugin-data-cloner`, `plugin-git-manager`, `plugin-hashicorp-vault-integration`; `plugin-embed-web-client` has it as a devDependency without tests. Manifest shape otherwise matches the brief (name = folder, `main`, `files` with `client-v2.js`, `nocobase.supportedVersions`/`editionLevel`); `displayName.zh-CN` is missing only in `plugin-data-cloner`.
6. **i18n discipline is uneven**: docker-registry-ui, database-plus-manager and vault are fully covered; git-manager zh-CN covers 17% of en; embed-web-client and external-storage-manager miss their own tab titles; data-cloner has empty locale files and hardcoded Vietnamese UI.
7. **Dead v1 scaffolding**: `src/client/models/index.ts` exporting `{}` and `flowEngine.registerModels({})` in `plugin-data-cloner` and `plugin-docker-registry-ui`; unused CSS-module shim `src/client-v2/client.d.ts` in docker-registry-ui.

#### Nhóm B3

1. **ACL snippet names vs server `this.name`**: with the default prefixes a custom `plugin-xxx` package's server `this.name` is the full package name. Plugins that build the server snippet from `pm.${this.name}` but hardcode a shortened name on the client are inconsistent: **plugin-idp-oidc-client-manager** (`pm.idp-oidc-client-manager.admin`) and **plugin-selector-registry** (`pm.selector-registry.*`). Consistent ones either hardcode the same literal on both sides (sftpgo, router-configuration, microsoft-graph-gateway) or derive both from the plugin name (n8n, package-registry via `this.options.name`). Recommend one convention: `pm.${this.options.name}` on the client, `pm.${this.name}` on the server. verify `PLUGIN_PACKAGE_PREFIX` once; if it contains `plugin-`, the two flagged plugins are fine.
2. **i18n namespace correctness** is the most common real defect: n8n uses a non-existent `@nocobase/plugin-n8n` namespace, router-configuration uses `useTranslation()` with no namespace, package-registry has no i18n at all. The correct v2 pattern (api-keys, sftpgo, selector-registry, oidc, graph-gateway) is `engine.context.t(key, { ns: [pkg.name, 'client'] })`.
3. **Lane sharing**: five of seven plugins share page code across lanes but place it inconsistently — under `src/client-v2/` imported by v1 (graph-gateway, selector-registry, sftpgo, router-configuration: allowed), under `src/client/` imported by v2 (package-registry: MEDIUM shared-code placement), duplicated verbatim in both lanes (n8n x13 files, oidc x2 files: MEDIUM). Only oidc has the recommended `src/shared/` folder and then does not use it from v2.
4. **Manifest nits repeated everywhere**: `files` ships `src` (n8n, package-registry, router-configuration, selector-registry, sftpgo); `peerDependencies` lists `@nocobase/test` (all seven); `@ts-ignore` on `package.json` imports (graph-gateway, selector-registry, oidc v1). None blocks a build.

#### Nhóm B4

1. **ACL snippet naming vs `this.name`** — the server side always uses `pm.${this.name}`, which for these unscoped packages is `pm.plugin-<name>...`. Three client conventions coexist in this group: literal `pm.plugin-uipath-orchestrator` (correct), `pm.${this.options.name}` (antd-style-theme v2, shared-forms — correct and self-adjusting), and hardcoded short names `pm.skill-registry.*` / `pm.user-memory.admin` (mismatch, MEDIUM in both). Every affected plugin has a test that passes `{ name: '<short-name>' }` and therefore cannot catch it. Recommend one shared rule: client snippets derive from `this.options.name`, and tests register plugins with the real package name.
2. **Lane-neutral code parked in `src/client/`** — antd-style-theme (theme UI tree, login theme, icon set), next-app-client (`hubRouteContract.ts`), user-memory (`MemorySettingsPage.tsx`) all have v2 importing `../client/...`. In all three cases the imported files already depend only on `@nocobase/client-v2`/antd, so the fix is a move to `src/shared/` (plugin-shared-forms already uses `src/shared/v2Config.ts`; skill-registry and uipath do it the other way round — v1 imports v2 pages — which is the allowed direction).
3. **`useT` helpers differ per plugin** — flow-engine `engine.context.t` with `pkg.name` (skill-registry, user-memory), react-i18next `useTranslation([pkg, 'client'])` (shared-forms, next-app-client), `app.i18n.t` with a wrong hardcoded `@nocobase/...` namespace (uipath). Standardise on `pkg.name` (or `this.options.packageName`) to avoid the uipath bug and the antd-style-theme namespace-copy hack.
4. **`@ts-ignore` on `import pkg from '../../package.json'`** appears in skill-registry and user-memory; a single `declare module '*.json'`/`resolveJsonModule` setting removes both suppressions.
5. **Manifest nits** — `@nocobase/test` listed as a runtime peer in 5 of 6 plugins; stale/unused `devDependencies` (`@formily/*` in uipath; the 16-entry list in antd-style-theme); `keywords` as a string in next-app-client. `name`, `main`, `files` (incl. `client-v2.js`), `displayName.zh-CN`, `nocobase.supportedVersions/editionLevel` are correct in all six.
6. **Tests** — present and behavioural for antd-style-theme (6), next-app-client (11), shared-forms (13), skill-registry (11), uipath (9); user-memory has none under `client-v2` (covered only from the v1 test file).

#### Nhóm C1

1. **Locale namespace != package name** is the most common defect in this group: `plugin-ai-drawio` (`'ai-drawio'`), `plugin-ai-browser` (`'ai-browser'`, patched at runtime by a resource-copy hack), `plugin-custom-llm` v1 (`'@nocobase/plugin-custom-llm'`). ## 6. Kế hoạch thực hiện sau hiệu chỉnh

### 6.1. Gỡ chặn kiểm chứng type và cố định baseline

- Xác nhận lại commit, working tree, Node/Yarn/TypeScript và phiên bản declaration trước khi sửa; lưu command, config, exit code và output kiểm chứng.
- Xác định cặp compiler/declaration tương thích cho lỗi import attributes trong `@types/sanitize-html`. Thử bằng cấu hình hoặc môi trường kiểm chứng tách biệt trước; không sửa tay `node_modules`, không dùng `skipLibCheck` như cách chữa lỗi cú pháp, không đổi toolchain/lockfile toàn repo như một sửa đổi custom plugin ngầm định.
